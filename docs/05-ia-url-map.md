## 0. Why this document exists

URLs are the hardest thing to change after launch. Every canonical, every `hreflang`
pair, every internal link, every indexed page and every external link pointing at the
site depends on them. Changing a URL later costs a redirect, a re-crawl, and a period
of degraded ranking.

So the full URL set is settled here, **before any route file is created** — not
discovered while coding.

attention both dilute with distance from the root.

## 2. URL conventions

Decided once, applied everywhere.

| Rule | Decision | Reason |
|---|---|---|
| Locale prefix | Always present, including default (`/en`, never `/`) | Symmetry; avoids duplicate-content between `/` and `/en` |
| Slug language | **ASCII English in all locales** — `/ar/projects`, not `/ar/مشاريع` | See §2.1 |
| Case | Lowercase only | Case-sensitive paths cause duplicates |
| Word separator | Hyphen | Underscores are not word separators to crawlers |
| Trailing slash | None (`trailingSlash: false`) | One canonical form; enforced by X-05 |
| File extensions | None | |
| Query parameters | None in v1 | Nothing to parameterise |
| Host | Apex, `www` 308s to apex | One canonical host (X-07) |

### 2.1 Slug language — the decision and its cost

Localised slugs (`/ar/مشاريع`, `/tr/hakkimda`) carry a **small** keyword benefit: the
slug is a minor ranking signal and localised URLs read better when shared.

Rejected anyway, because:
- Arabic slugs percent-encode to `/ar/%D9%85%D8%B4%D8%A7%D8%B1%D9%8A%D8%B9` — ugly in
  shares, error-prone in `hreflang` and canonical tags, and a frequent source of
  double-encoding bugs.
- Turkish slugs need dotless-`ı` handling; `hakkımda` vs `hakkimda` is a duplicate
  waiting to happen.
- Three slug sets triple the mapping surface for the language switcher (I-09).

For a 12-route site the keyword gain is negligible against the bug surface. **If this
is revisited later**, it requires 301 redirects from every old URL — which is exactly
why it is being decided now rather than drifted into.

## 3. `hreflang` matrix

Every route emits **four** `<link rel="alternate">` tags: three locales plus
`x-default`. Reciprocity is mandatory — if A declares B, B must declare A.

Example, for the Projects page (identical pattern on all four page groups):

```html
<link rel="alternate" hreflang="en"        href="{ORIGIN}/en/projects" />
<link rel="alternate" hreflang="tr"        href="{ORIGIN}/tr/projects" />
<link rel="alternate" hreflang="ar"        href="{ORIGIN}/ar/projects" />
<link rel="alternate" hreflang="x-default" href="{ORIGIN}/en/projects" />
```

| Rule | Value |
|---|---|
| `x-default` | Always the `en` equivalent of the same page |
| Language codes | Bare (`en`, `tr`, `ar`) — **not** `en-US`/`tr-TR`. The site targets languages, not countries |
| URLs | Absolute, canonical form, no trailing slash |
| Self-reference | Each page includes itself in its own set |
| Non-indexable locales | A locale failing I-14 (`_meta.reviewed = false`) is **removed from all `hreflang` sets**, not merely dropped from the sitemap |

**The I-14 interaction is the subtle one.** Pointing `hreflang` at a `noindex` page is
a contradictory signal and a common Search Console error. The alternates generator must
read the same `_meta.reviewed` flag the robots directive does — one source of truth,
consumed in two places.

Implementation: one `buildAlternates(locale, pathname)` helper, used by
`generateMetadata` on every route. No route hand-writes its alternates.

## 4. Internal linking

With 12 routes, internal linking is not about equity sculpting — it is about making
sure every page is reachable and every locale forms a closed graph.

### 4.1 Rules

| Rule | Detail |
|---|---|
| Never cross locales in body links | A link from `/ar/about` goes to `/ar/projects`, never `/en/projects`. The only cross-locale links on the site are in the language switcher |
| Switcher links carry `hreflang` + `lang` | Signals the target language to crawlers and screen readers (A-11) |
| Every page links to every other page | Via the header nav — satisfies reachability with no extra work |
| Descriptive anchor text | Localised and meaningful. No "click here", no "read more" |
| External links | `rel="noopener"`; `rel="me"` on GitHub and LinkedIn (F-43) |
| Repository links | `target="_blank"` with an accessible indication that the link opens externally |

### 4.2 Deliberate link paths

Beyond the navigation, these contextual links exist on purpose:

```
/{locale}            → /{locale}/projects    (project cards)
/{locale}            → /{locale}/contact     (primary CTA)
/{locale}/about      → /{locale}/projects    ("see what I've built")
/{locale}/projects   → /{locale}/contact     ("interested? get in touch")
/{locale}/404        → /{locale}             (recovery)  — NOT BUILT, see below
```

**Status (T-218).** Four of the five links are implemented. The Home → Projects
link is the project cards themselves, which link to each project's section on
`/projects` via `projectAnchor()` — the same function `/projects` renders its
`id` attributes from, so the two cannot drift into dead fragments.

The **404 → Home** link does not exist, because the localised 404 page does not
exist: `dynamicParams = false` on `[locale]` prevents a `[locale]/not-found`
boundary from being reached, and both restructures were measured and rejected
(T-214, deferred to **T-320**). The link ships with that page, not before. The
`notFound.backHome` copy is already written in all three locales.

`scripts/verify-links.mjs` enforces §4.1 and §4.2 against the prerendered HTML:
no body link crosses locales, every page links to every other, and `/projects`
carries strictly the most inbound internal links.

Rationale: Projects receives the most inbound internal links because it is the page
that converts a recruiter, and the page whose keywords are the most winnable
(`02-keyword-plan.md` §3.1). Contact is the terminal node in every path.

### 4.3 `rel="me"` and the name entity

GitHub and LinkedIn links carry `rel="me"`, and both profiles should link back to the
domain. This bidirectional confirmation is what lets search engines merge three
profiles and one site into a single `Zeyad Alnahdi` entity — the mechanism behind
goal G1, and worth more than any on-page keyword work here.

## 5. `sitemap.ts` design

Generated, never hand-written.

```
For each locale L in [en, tr, ar] where messages[L]._meta.reviewed:
  For each page P in [/, /about, /projects, /contact]:
    <url>
      <loc>{ORIGIN}/{L}{P}</loc>
      <lastmod>{build date, or per-page content mtime}</lastmod>
      <xhtml:link rel="alternate" hreflang="{each reviewed locale}" .../>
      <xhtml:link rel="alternate" hreflang="x-default" href="{ORIGIN}/en{P}" />
    </url>
```

| Rule | Value |
|---|---|
| Entry count | 12 when all locales reviewed; 8 if one locale is gated; 4 if two are |
| `changefreq` / `priority` | **Omitted.** Google ignores both; including them is noise |
| `lastmod` | Only if genuinely accurate. A `lastmod` that always equals build time is a false signal and is ignored — or distrusted |
| Excluded | `noindex` routes, 404, OG image routes |
| Alternates | Mirrors §3 exactly. Same helper, same source of truth |

## 6. `robots.ts` design

```
User-agent: *
Allow: /

Sitemap: {ORIGIN}/sitemap.xml
```

| Rule | Detail |
|---|---|
| Production | As above — allow everything. There is nothing on this site to hide from crawlers |
| Preview / non-production | `Disallow: /` **and** an `X-Robots-Tag: noindex` response header (X-06). The header is what actually protects you; `robots.txt` alone does not prevent indexing of a URL that is linked elsewhere |
| Detection | Branch on `VERCEL_ENV === 'production'`, never on `NODE_ENV` — preview builds are production builds |

## 7. Route → file map

```
app/
├── layout.tsx                      root; <html lang dir> set per locale
├── robots.ts
├── sitemap.ts
├── not-found.tsx
└── [locale]/
    ├── layout.tsx                  locale provider, header, footer
    ├── page.tsx                    /{locale}
    ├── opengraph-image.tsx
    ├── about/page.tsx              /{locale}/about
    ├── projects/page.tsx           /{locale}/projects
    └── contact/page.tsx            /{locale}/contact

lib/seo/
├── origin.ts                       {ORIGIN} from env, validated at build
├── alternates.ts                   buildAlternates() — §3, single source of truth
├── metadata.ts                     buildMetadata() — M-01..M-08
└── schema.ts                       JSON-LD graph — S-01..S-07

messages/
├── en.json
├── tr.json                         _meta.reviewed gates indexing (I-14)
└── ar.json
```

**`generateStaticParams`** returns all three locales on every route group, producing
12 static pages at build time (§1 of `04-srs.md`).

**The `lib/seo/` module is built in Sprint 1, before any page exists.** This is the
structural expression of the project's governing principle: if SEO helpers are written
after the pages, they get retrofitted page by page and drift. Written first, every page
is forced through them.

## 8. Redirect map

| From | To | Status |
|---|---|---|
| `/` | `/en` | 308 |
| `/about`, `/projects`, `/contact` (no locale) | `/en/{path}` | 308 |
| `www.{domain}/*` | `{domain}/*` | 308 |
| `http://*` | `https://*` | 308 |
| `/{locale}/{path}/` | `/{locale}/{path}` | 308 |

308 rather than 301: permanent and method-preserving, and the correct default for
Next.js `redirects()`.

## 9. Decisions recorded here

| # | Decision | Rationale |
|---|---|---|
| A1 | Locale prefix on default locale | Avoids `/` ↔ `/en` duplication |
| A2 | ASCII English slugs in all locales | §2.1 |
| A3 | Bare language codes, no region | Targets languages, not countries |
| A4 | Flat depth-1 structure | 12 routes need no hierarchy |
| A5 | No `changefreq`/`priority` in sitemap | Ignored by Google |
| A6 | `x-default` → `en` | Widest audience is the English one |
| A7 | One `buildAlternates` helper | `hreflang` errors come from hand-written, drifting tags |
